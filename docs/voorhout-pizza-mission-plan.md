## 1. Goal and definition of done

A 40–50 second vertical video that looks like a photorealistic open-world
crime-game mission set in the real Voorhout: a delivery rider leaves New York
Pizza on the Herenstraat, is stopped by the closing barriers at the station
level crossing while a train passes, then delivers the pizza on time. The
reaction we want from locals: "wow, that is my village in a game".

Done means:

1. `press/nyp-voorhout-hot-slice.mp4`: 1080x1920, H.264 (yuv420p, faststart) +
   AAC, 40–50 s, integrated loudness -14 LUFS (±0.5), true peak ≤ -1 dBTP.
2. Seven generated shots, game HUD overlay, music bed, sound effects, real shop
   logo on the end card.
3. The owner recognises the shop front and the crossing without being told.
4. A reusable Flow driver exists (`tools/flow_driver/`) that takes a shot list
   and produces downloaded clips, so the next ad is a manifest change.
5. Lab notebook entry appended.

## 2. Hard constraints (do not relitigate)

- **No Rockstar IP.** No "GTA", no "Jason", no game logo, no Pricedown-style
  title font, no copied HUD layout, no music from the game. Original parody of
  the genre with an original hero (working name Daan).
- **Hero waits at the crossing.** He never passes a lowering or closed barrier
  and never races the train.
- **No text or logos generated by the model.** All text, HUD and the logo are
  added in the edit.
- **No readable real number plates, no recognisable bystanders** in reference
  photos or final frames.
- **Credits are real money.** Nothing clicks "Create" for a video without the
  spend gate in section 9. Read costs live; never assume them.
- **One Google account, human pace.** No stealth, fingerprint or multi-profile
  modules. One generation in flight at a time, at least 45 s between submissions.
- **Do not edit the `nexy_v2` repo** for this job. Read it, copy techniques.
- **Free tools first:** ffmpeg, Playwright, royalty-free audio.

## 4. Realism bible (already folded into `shots.json`; keep when rewriting prompts)

- **Streets:** red-brown brick paving, red asphalt cycle lanes, white "shark
  teeth" give-way triangles, low brick terraced houses with orange tile roofs,
  blue street-name signs, many parked bicycles. Traffic keeps right.
- **Vehicles:** small European hatchbacks and vans. Dutch plates are yellow with
  black characters and a blue EU strip; keep them soft and unreadable.
- **Scooter:** red electric delivery scooter, insulated rear box, small yellow
  plate. The logo on the box is added in the edit.
- **Crossing:** red and white striped half barriers, St Andrew's cross sign,
  two alternating red lights, ringing bell, overhead wires above two tracks.
- **Train:** yellow Dutch passenger train with blue and white bands.
- **Landscape:** flat, big sky, straight ditches, bulb fields. The game world is
  set in spring (tulips in bloom) even though we shoot in November.
- **Light:** low golden-hour sun, long shadows, slightly heightened colour.

### Post-production recipe (from `creative-forge/processor.py`, copy the filter strings, do not import)

- Music under clip audio: `sidechaincompress=threshold=0.08:ratio=3:attack=20:release=400:makeup=5`,
  music volume about 0.32, `amix=...:normalize=0` (lines 3498-3529).
- Loudness: `loudnorm=I=-14:LRA=11:TP=-1.5` (lines 3621-3638). Use the two-pass
  form and verify with `ebur128`; the repo only does single pass and never measures.
- Skip its `scale_and_crop`: it re-encodes at low quality and adds a colour grade.

### 8b. Decide the character-consistency route (written before testing)

Prediction: Flow will not accept a start frame and a character reference in the
same video generation. If so, use **route K**; if it does, use route D.

- **Route K (keyframes, preferred):** first make a still per shot with Flow's
  image generation: location photo + hero image + `keyframe_prompt`. Then run
  frames-to-video from that still with `video_prompt`. The still fixes both the
  real place and the same hero, and stills are cheap to review before video credits are spent.
- **Route D (direct):** start frame = location photo, reference = hero image, one generation.
- **Route T (fallback):** if image generation with references is not available,
  frames-to-video from the raw location photo with the hero described in a fixed
  text block in every prompt. Expect more drift; say so to the owner.

### 8c. Build `tools/flow_driver/flow_driver.py`

One file, Playwright async, reads `ads/nyp-voorhout/shots.json` and `selectors.json`.

| Command | Behaviour |
|---|---|
| `probe` | Attach, list tabs, read credit balance, screenshot. Spends nothing |
| `still --shot N` / `--hero` | Generate a keyframe (route K) into `ads/nyp-voorhout/keyframes/` |
| `video --shot N --take K --dry-run` | Do everything up to, not including, Create; screenshot the filled prompt bar |
| `video --shot N --take K --yes-spend` | One generation, wait, download to `ads/nyp-voorhout/raw/sN_tK.mp4` |
| `run --shots 4,5 --takes 1 --max-credits C --yes-spend` | Loop with pacing and resume |
| `status` | Table of shots × takes: missing, generating, downloaded, rejected |

Required behaviour (each one answers a verified failure in `nexy_v2`):

1. **Single spend path.** Only one function clicks Create. It reads the live
   cost label, refuses if the cost is unreadable, if `spent + cost > --max-credits`,
   or without `--yes-spend`, and appends `{shot, take, cost, balance_before, balance_after, time}`
   to `runs/ledger.json`. No retry ever re-clicks Create automatically.
2. **Completion tied to this submission.** Snapshot the result tiles (ids or
   video addresses) before Create; done means a new tile with a playable video.
   Errors are read from that tile only, never from page-wide text. Timeout 600 s.
3. **Verified settings.** After setting aspect, outputs, model and mode, read
   them back; abort before Create if any differs from the manifest.
4. **Login-aware download.** Try in order: Flow's own download with Playwright's
   download event and `save_as`; an in-page `fetch(url, {credentials: 'include'})`
   returned as bytes; watching `~/Downloads` for the new file. Then `ffprobe`:
   7–9 s, height greater than width, has an audio stream, larger than 500 KB.
   A failed check marks the take "download_failed", it does not regenerate.
5. **One project for the whole ad**, reused across runs, so uploaded images stay available.
6. **Resume.** `runs/state.json` per shot and take; anything already downloaded and valid is skipped.
7. **Pacing.** One generation in flight; at least 45 s between submissions.
8. **Prompts untouched.** Send `style_prefix + video_prompt + audio_prompt` as
   written; no sanitiser.

Acceptance before any video credit is spent: `probe` passes; `video --shot 4 --take 1 --dry-run`
ends with a screenshot showing the right mode, image attached, 9:16, the
prompt text, and the cost label; a second agent reviews the driver against the
eight rules above and tries to find a path that clicks Create twice.

## 10. Reject list for stills and takes

- Hero's face or outfit changes between shots.
- Any invented text, logo or sign that reads as gibberish.
- Hero moves past a lowering or closed barrier; barriers pass through objects.
- Train on the road side of the barriers or off the rails.
- Traffic on the left, non-European cars, white or US-style plates, readable plates.
- Hills, palm trees or anything that is not flat Dutch landscape.
- Real buildings from the reference photo visibly altered.
- Missing audio stream, or speech that is not Dutch where speech was asked for.

## 12. Stage 4 — Edit, sound, verify (same Mac session)

**Pick takes.** `ffprobe` each clip, view frames, choose one take per shot.

**HUD (original design, three independent pieces; can be built in parallel by
sub-agents while generation runs, since they do not need the clips):**

- *Minimap:* circular, bottom left, drawn from real OpenStreetMap street
  geometry around 52.2219–52.2245 N, 4.480–4.487 E (Overpass API), route line
  from the shop to the crossing, player arrow advancing per shot. Credit
  "© OpenStreetMap contributors" in the video description.
- *Mission text and timer:* title card "HOT SLICE" on shot 1; objective
  "Bezorg de pizza voordat hij koud wordt" on shot 2; countdown timer top right
  that turns red on shot 4 and resumes on shot 5; "Obstakel gepasseerd" on shot 5.
- *End card (3 s):* "MISSIE GESLAAGD", the real logo file, "Herenstraat 112, Voorhout",
  the offer and order link.

Render overlays as transparent PNG sequences from HTML/CSS with Playwright, or
with ffmpeg `drawtext`/`overlay` and `enable='between(t,a,b)'`. Font: an
open-licensed bold condensed face (Anton or Bebas Neue), not a game font.

**Assemble.** Trim each shot to 5–6.5 s on the action, hard cuts, order 1–7,
end card last, target 42–48 s. Normalise every clip first to 1080x1920, 30 fps,
48 kHz stereo; encode once at the end (libx264 crf 18, preset slow, yuv420p, `+faststart`).

**Sound.**

- Keep the clips' native audio as the effects layer.
- Music bed: one royalty-free instrumental, synthwave or West Coast style,
  100–110 BPM, from a library whose licence allows commercial use. Record title,
  author and licence URL in the notebook. If none is reachable, ask the owner for `refs/music.mp3`.
- Duck the music under the bell and train on shots 4–5 with the sidechain
  recipe in section 5; bring it back on the cut to shot 6.
- UI sounds synthesised with ffmpeg: mission-start sting, timer tick on shot 4, success chime on the end card.
- Two-pass loudnorm to -14 LUFS, true peak -1 dBTP.

**Verify (a different agent than the editor, told to refute).** Give it the
output file plus sections 1, 2 and 10. It checks duration, resolution, pixel
format, measured loudness (`ffmpeg -af ebur128`), then one frame per second for
garbled text, wrong logo, readable plates, HUD covering faces, and any frame
where the hero is past a closed barrier.

**Ship.** Save to `press/`, commit the driver, manifest, selectors and final
video (not `raw/` or `runs/`; add them to `.gitignore`), push, open or update
the pull request. Posting to social media is the owner's decision.

## 13. Law 1 record

- **Constraint (Law 2):** knowledge of today's Flow UI. Until stage 2 measures
  it, every downstream step is a guess. After stage 2 the constraint moves to
  credits per usable take, which the keyframe review (G1) is designed to cut.
- **Hypothesis 1 — killed 2026-11-20:** "`nexy_v2` can generate our clips as
  is." Test: full code read with independent verification. Result: no custom
  prompts, no image input, campaign-bound entry point, eleven-month-old selectors.
  Kept: attach recipe, stable ids, discovery tools, credit read.
- **Hypothesis 2:** if each shot starts from a keyframe that composites the hero
  into a real photo of the Herenstraat, and all text is added in the edit, then
  locals recognise the place and the hero stays the same person, because the
  video model preserves a start frame far better than it invents a specific
  village or re-creates a face from words.
- **Predictions (written before generating):** (a) Flow refuses start frame plus
  reference in one generation; (b) the owner recognises shots 1, 2, 4 and 5
  from the stills alone; (c) shot 5 needs three or more takes; (d) cost per fast
  video generation is 20 credits.
- **Cheapest falsifying tests, in order:** stage 2 discovery (free), G1 stills, G2 crossing shots.
- **Pre-mortem (public ad, hard to recall once posted):** franchise objects to
  logo use (covered by stage 0); takedown for resembling the real game (section 2);
  credits burned by a double click or a wrong setting (driver rules 1 and 3);
  hero drifts (route K); automation eats the day (time box and section 11).
